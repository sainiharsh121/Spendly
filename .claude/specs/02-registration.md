# Spec: Registration

## Overview
Turn the static `/register` page into a working sign-up flow. A visitor submits name, email and password; the server validates the input, stores a new row in `users` with a werkzeug-hashed password, and redirects to the login page with a success notice. This is the first feature that writes user data and builds directly on the data layer from Step 1. Login and session handling are deliberately left to Step 3, so registration does not log the user in.

## Depends on
- Step 1 — Database setup (`get_db()`, `init_db()`, `users` table with `UNIQUE` email).

## Routes
- `GET /register` — render the registration form (already exists) — public
- `POST /register` — validate the form, create the user, redirect to `/login?registered=1` on success or re-render the form with an error on failure — public

The existing `register` view function keeps its name (templates use `url_for('register')`) and is changed in place to accept both `GET` and `POST`.

## Database changes
No database changes. The `users` table in `database/db.py` already has `name`, `email` (`UNIQUE`, `NOT NULL`), `password_hash` and `created_at` (defaults to `datetime('now')`). Duplicate emails are rejected both by an explicit lookup and by catching `sqlite3.IntegrityError` on insert.

## Templates
- **Create:** none
- **Modify:**
  - `templates/register.html` — change `action="/register"` to `action="{{ url_for('register') }}"`; re-populate `name` and `email` inputs from submitted values on error (never the password); keep the existing `{% if error %}` block.
  - `templates/login.html` — show a success message above the form when the page is loaded with `?registered=1` (pass a `registered` flag from the view, or read `request.args`).

## Files to change
- `app.py` — import `request`, `redirect`, `url_for`, `sqlite3`, `generate_password_hash`; implement `POST /register`; make the `login` view pass `registered=request.args.get("registered")` to its template.
- `templates/register.html`
- `templates/login.html`
- `static/css/style.css` — add an `.auth-success` style next to the existing `.auth-error`, built only from existing CSS variables.

## Files to create
- `tests/test_registration.py` — pytest + pytest-flask tests for the registration flow (uses a temporary database; must not touch the real `spendly.db`).

## New dependencies
No new dependencies.

## Rules for implementation
- No SQLAlchemy or ORMs
- Parameterised queries only — no string formatting in SQL
- Passwords hashed with werkzeug (`generate_password_hash`); never store or log the plain password
- Use CSS variables — never hardcode hex values
- All templates extend `base.html`
- Keep route function names unchanged (`landing`, `login`, `register`, ...)
- Use `get_db()` from `database/db.py`; always close the connection (`try/finally`)
- Server-side validation (the HTML `required` attributes are not enough):
  - `name`: trimmed, non-empty
  - `email`: trimmed, lower-cased, non-empty, contains `@` with text on both sides
  - `password`: at least 8 characters (matches the form placeholder)
- Error messages are plain strings passed as `error` to the template; do not reveal anything beyond "An account with this email already exists." for duplicates
- Do not add sessions, `secret_key` or `flask.flash` — that belongs to Step 3
- Do not change the other placeholder routes

## Definition of done
- [ ] `GET /register` still renders the form with status 200
- [ ] Submitting valid name, email and an 8+ character password creates exactly one new row in `users` and redirects (302) to `/login?registered=1`
- [ ] The stored `password_hash` is a werkzeug hash (not the plain password) and `check_password_hash` accepts the original password
- [ ] The login page shows a success message when loaded with `?registered=1` and not otherwise
- [ ] Registering with an email that already exists (e.g. `demo@spendly.com`, also in a different letter case) re-renders the form with an error and does not create a second row
- [ ] Empty name, invalid email, or a password shorter than 8 characters re-renders the form with a specific error and creates no row
- [ ] On any error the name and email fields keep their submitted values and the password field is empty
- [ ] The form posts to the URL generated by `url_for('register')`
- [ ] `pytest tests/test_registration.py` passes
- [ ] App starts with `python app.py` without errors and no hardcoded hex colours were added to `style.css`
